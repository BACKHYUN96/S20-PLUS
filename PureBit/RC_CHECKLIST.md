# BITWIRE 1.0.0 실기기 최종 점검

RC1 적용 후 앱이 잘 동작한다는 사용자 피드백을 받았다. 각 항목별 결과가 전달된 것은 아니므로 전체 합격으로 표시하지 않는다.

같은 package/서명, versionCode33의 업데이트 APK를 사용한다. 삭제/캐시·데이터 초기화는 하지 않는다. 아래 결과는 아직 미실행이다. 각 항목을 ORIGINAL과 화현에서 확인하고 문제가 있으면 설정 → 앱 내부 데이터의 진단/오류 기록을 공유한다. APK 빌드와 JVM 테스트는 Android 통합 테스트를 대신하지 않는다.

처음에는 익숙한 낮은 볼륨으로 확인한다. native USB44.1kHz는 여전히 지원하지 않으며 자동 SRC/fallback은 없다. 다른 DAC 호환성, gapless, DAC 수신 데이터의 bit-perfect, 실제60FPS는 이번 RC가 새롭게 보장하지 않는다. 기기에서 실패한 항목이 있으면 정식1.0 확정보다 해당 수정이 우선이다.


## RC2 대기열 추가 확인

1. 세 곡 이상으로 셔플 ON/반복 OFF. 한두 곡을 들은 뒤 현재 곡 이외의 순서를 옮기거나 아직 듣지 않은 곡을 제거한다. 이미 들은 곡이 편집 때문에 다시 후보로 들어가지 않고 남은 후보를 소비하면 멈춰야 한다. 끝부분 탐색으로 자연 종료에 가깝게 이동해도 된다.
2. 셔플 도중 저장 목록에서 새 곡을 끝에 담거나 ‘다음에 재생’으로 추가한다. 현재 재생/위치/출력/볼륨은 유지되고 새 후보가 중복되지 않아야 한다. 이미 들은 곡을 직접 선택하거나 다음 재생으로 요청한 재청취는 허용한다.
3. 단일 곡/전체 반복/한 곡 반복과 수동 NEXT를 확인한다. 셔플을 OFF→ON 하면 새 pass가 만들어진다. 대기열 이동/삭제만으로 pass가 재시작하면 안 된다. 저장 목록 순서와 실행 셔플 후보 순서는 별개다.
4. 소스가 없는 빈 세션이 이미 있다면 곡 길게 누르기 → 다음에 재생. 자동 재생 없이 QUEUE READY와 PLAY가 가능해야 한다. 첫 곡이 끝난 뒤 자기 자신을 priority-next로 다시 재생하지 않아야 한다. 이 경우를 만들기 위해 기존 데이터를 지우지는 않는다.
5. 진단 소스 재생은 음악의 최근 재생/이어듣기 기록을 덮어쓰지 않아야 한다. 콜드 이어듣기 선택 뒤 큐에 곡을 추가해도 저장 위치가0으로 바뀌지 않는지 확인한다.


## v1.0.0 마지막 수정 확인

1. Android/USB 각각 일시정지 → 탐색을 확정 → 즉시 PLAY. 이전 위치 대신 확정 위치에서 재생해야 한다. 재생 중 탐색 확정 직후 PAUSE, PAUSE→PLAY 연타, 잠금화면 탐색과 PLAY도 확인한다. 취소된 드래그는 이동하지 않아야 한다.
2. 확정 직후 다른 앱 오디오/전화/USB 분리가 발생하면 자동 재개 없이 멈추고, 정상 연결/볼륨 확인 후 명시적인 PLAY로 재개한다. 실제 Samsung 이벤트 순서와 정확한 샘플 단위 위치는 여기서 검증됐다고 가정하지 않는다.
3. 알림 중지 직후 다른 곡 선택, 일시정지5분 이상 뒤 새 곡 선택/이전/다음, 빠른 연속 선택. 최신 선택이 준비된 서비스에서 시작되고 이전 서비스 정리 때문에 멈추지 않는지 확인한다. 대기 중 출력 모드/진단 소스 변경/분리는 오래된 음악을 갑자기 시작하지 않아야 한다.
4. 서비스 시작이 OS 정책으로 거부되는 경우 앱이 종료되지 않고 오류/정지로 알려야 한다. 이 경우 앱으로 돌아와 곡을 다시 선택한다. 실제 FGS 예외/Service teardown 통합은 JVM 모델 테스트만으로 확인할 수 없다.
5. 큰 글꼴에서 미니 플레이어 제목/아티스트/버튼, 긴 한글·영문 곡명, 가로·세로·키보드와 두 테마를 확인한다. 이어폰 분리 안내가 화현에서도 사라지지 않는지 확인한다.
