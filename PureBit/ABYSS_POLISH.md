# BITWIRE v1.10.0 / code 47 — ABYSS 기존 디자인 폴리싱

## 실제 화면에서 확인한 문제와 수정 근거

사용자 제공 v1.9.0 녹화(17.81초)에서 긴 두 줄 제목 아래의 A–B/가사 행이 초기 화면 밖으로 밀렸다. 사용자의 후속 스크린샷에서 스크롤하면 해당 행이 나타나는 것을 확인했다. 코드의 전망창 최소 높이가 콘텐츠 너비의 98%로 고정되어 남은 높이보다 커져도 줄지 않는 것이 원인이다. 같은 영상에서 전경 해파리가 제목과 하단 메뉴 위를 밝게 통과했다.

대규모 리팩터링, 새 배경, 새 3D/영상 시스템을 도입하지 않았다. 작은 원형 앨범과 클릭 전환을 유지한다. 재생·일시정지·탐색·USB 하드웨어 볼륨·A–B·가사·스킨 전환의 명령 경로는 변경하지 않았다. A–B/가사를 다른 메뉴로 옮기거나 제거하지 않았다.

## 성능 영향

- 추가: 전경 개체와 최대 16개 보호 영역의 간단한 거리 계산, 라벨 3개의 약한 텍스트 그림자, 재생 구체의 얕은 음영 1회 그리기.
- 감소: 프레임마다 만들던 배경·앨범 그라데이션을 재사용하고, 해파리 메시의 고정 행/열 계산을 캐시. 사용하지 않는 기포 이미지 메모리 로딩 제거.
- 새로운 오프스크린 레이어/화면 캡처/3D 시뮬레이션은 없다. 실제 CPU/GPU 사용률·배터리·프레임 안정성은 이 환경에서 측정하지 못했다. 성능 향상을 실측했다고 주장하지 않는다.

## 자동 검증과 실제 화면 검증 구분

JVM 검사는 높이 예산에서 조작부가 들어가는지, 큰 글꼴·확장 도구의 스크롤 보존, 원형 지오메트리/터치 영역, 부드러운 감쇠 경계, 메시의 결정성/열 역전 방지를 검사한다. Gradle/Lint 결과는 VALIDATION.md에 기록한다.

이 환경에는 연결된 Galaxy와 실행 가능한 Android 에뮬레이터 이미지가 없다. **새 버전의 실제 앱 화면 캡처·애니메이션 전후 비교는 아직 수행하지 못했다. 시각 검증 완료가 아니다.** 이전 영상만 확인했고 가짜 수정 후 스크린샷이나 합성 화면을 검증 자료로 만들지 않았다.

미확인/유지된 한계:

- 기본 설정의 S26 Ultra 실제 화면에서 A–B/가사가 스크롤 없이 보이는지 확인 필요. 진단 수치는 보조 자료일 뿐 실제 화면의 증명이 아니다.
- 큰 글꼴, A–B 상세 확장, 작은 창/화면, 고정 높이 외부 테마에서는 스크롤을 의도적으로 허용한다.
- 해파리는 기존 PNG 메시이며 독립적인 3D 촉수나 실제 유체 시뮬레이션이 아니다. 먼 개체는 대비/크기로 표현하며 새 블러 필터는 적용하지 않는다.
- 실제 UI 영역 기반 감쇠는 메인 재생 화면에 적용했다. 별도 가사/몰입 오버레이의 개별 글자 영역은 이번 패치의 감쇠 등록 범위가 아니다.

## S26 Ultra에서 필요한 비교 자료

기존 앱 위에 업데이트 설치한다. 제거/데이터 초기화는 필요 없다.

1. 이전과 같은 `Jon Snow (Feat. DEAN) (Prod. by Lnb)`를 선택하고, 기본 글자 크기·동일한 효과 설정으로 재생 화면을 맨 위로 올린다.
2. A–B/가사와 하단 메뉴가 함께 보이는 전체 스크린샷 1장, 10~15초 녹화를 전달한다. 제목·버튼 근처를 지나는 해파리와 기포를 비교한다.
3. A–B를 펼쳐 A/B 지정·반복·해제, 가사 열기, 재생/일시정지·탐색·볼륨을 확인한다. 드래그 중 기존 음악 유지와 놓을 때 이동을 확인한다.
4. 가로 회전 및 ORIGINAL/화현 복귀, 큰 글꼴을 확인한다. 이 경우 스크롤 허용은 정상이다.
5. 여전히 기본 화면이 넘치면 `설정 → 앱 내부 데이터`의 전체 진단도 전달한다. VISUAL LAYOUT에 마지막 viewport/controls/hero/overflow 수치가 포함된다.

이 자료를 받은 뒤 수정 전 영상과 실제 수정 후 화면을 비교하고 남은 차이를 보고한다.
