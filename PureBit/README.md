## v1.0.0 사용 안내

동일한 `app.purebit`/서명, versionCode33의 기준 빌드다. 기존 앱 위에 설치하며 라이브러리/재생목록/테마/즐겨찾기/이어듣기 저장 형식은 유지한다. 버전명1.0.0은 Galaxy의 모든 통합 항목이나 실제 DAC bit-perfect를 검증했다는 의미가 아니다. 확인된 범위와 남은 기기 항목은 [RC_CHECKLIST.md](RC_CHECKLIST.md), 빌드 근거는 [VALIDATION.md](VALIDATION.md)에 구분한다.

- **확정 탐색과 재생/정지:** 일시정지 상태에서 손을 놓아 탐색을 확정한 직후 PLAY/TOGGLE을 눌러도 대기 중인 목표를 버리지 않고 그 위치에서 재개한다. 확정 직후 PAUSE/포커스 손실/물리 USB 분리는 목표를 유지하되 자동 재개를 철회한다. 화면에서 아직 드래그 중인 미리보기는 여기에 해당하지 않으며 기존처럼 취소하면 이동하지 않는다. USB close 중 새 명령이 오면 오래된 seek가 새 의도로 자동 재개하지 않도록 마지막에 세대를 재확인한다. 출력/소스 변경의 기존 취소 규칙은 유지한다.
- **foreground 서비스 소유권:** 새 소스의 자동 재생 load는 활성 foreground owner가 준비된 뒤에 실행한다. 종료가 수락된 owner는 즉시 ready 상태를 철회하고, 대기 중 선택은 최신 요청 하나로 합친다. 새 owner가 시작된 뒤 도착하는 이전 owner의 onDestroy는 새 출력에 pause를 보내지 않는다. 은퇴한 owner의 상태/앨범아트 콜백도 새 알림을 갱신하지 않는다. stopSelfResult에 startId를 전달해 system_server에 더 최신 시작이 등록된 경우 이전 종료 요청이 foreground를 제거하지 않게 한다. MediaSession 제어는 현재 owner이면 순서대로 처리하고, 은퇴한 owner이면 서비스 Intent로 전달한다. 은퇴한 세션의 탐색/볼륨 콜백은 현재 출력을 조작하지 않는다.
- **대기 요청 취소/실패:** 직접 파일 선택, 출력/정책 변경, 진단 준비, 포커스 상실/USB 분리/noisy 신호는 대기 중 음악 시작을 취소한다. 새 소스가 대기 중이면 이전 EOF가 새 큐를 넘기지 않게 한다. FGS 시작이 예외로 거부되면 큐 티켓을 취소하고 엔진 오류/정지로 알린다. 앱으로 돌아와 곡을 다시 선택해 시도한다. 콜드 이어듣기 위치는 실제 load가 시작될 때까지 유지한다. 프로세스가 죽은 뒤 자동으로 서비스를 되살려 재생하는 기능은 추가하지 않는다.
- **화면 정리:** 미니 플레이어의 곡명/아티스트 영역은 최소 높이+내용 높이로 배치해 큰 글꼴에 공간을 준다. 긴 메인 곡명은2줄 뒤 말줄임, Android 이어폰 경로 변경 정지는 별도 안내를 표시한다. 실제 최대 글꼴/가로 모드/프레임 시간/발열과 메모리는 기기 확인이 필요하다.

## v0.4.4: 재생을 유지하는 드래그 / 에너지 파형

**이 버전은 아래 v0.4.3의 '드래그 시작 시 일시정지' 동작을 대체한다.** 재생 중 드래그해도 현재 위치에서 음악이 계속 진행한다. 탐색 미리보기는 source/intent token만 보관하며 AudioTrack pause, USB native fence/close, seek 또는 PCM 변경을 호출하지 않는다. 선택 시간과 현재 재생 시간을 따로 보여주고, 손가락을 놓았을 때만 최종 위치로 한 번 탐색한다. 원래 일시정지 상태였다면 이동 후에도 정지를 유지한다. 실제 위치 전환에는 기존 출력 재준비 지연이 발생할 수 있다.

터치 취소/다른 화면/백그라운드 전환은 미리보기만 버리고 기존 재생을 유지한다. 별도로 발생한 pause/focus loss/USB 분리/다른 곡/출력 변경/다른 탐색은 기존 transport 정책대로 처리하며, 이전 gesture release가 이를 되살리지 않는다. 드래그 중 자연스럽게 곡이 끝나고 다음 곡으로 바뀐 경우에도 이전 선택을 새 곡에 적용하지 않는다. A–B 범위/해제/반복 정책은 유지한다.

하단 overview의 굵은 파형은 각 시간 구간의 **모든 채널 sample power로 구한 RMS**로 그린다. 채널을 평균한 후 제곱하지 않으므로 반대 위상 stereo도 지워지지 않는다. column에 여러 bucket이 들어오면 실제 sample 수로 power를 가중 평균한다. 원래 signed min/max peak는 가늘고 옅은 배경으로 보존한다. 기존 최대 peak만 굵게 그릴 때, 마스터링으로 peak가 비슷한 곡 전체가 가득 찬 막대로 보이던 현상을 줄인다.

표시 곡선은 `height = 0.9 × RMS^1.25`로 고정하며 최대 밝은 본체에도 여백을 둔다. 곡마다 최대값으로 다시 키우는 auto gain이나 가짜 강약/리듬은 넣지 않는다. 실제 에너지가 일정한 소스는 본체도 일정하게 보일 수 있다. 대칭 본체는 에너지 envelope이고, 부호가 있는 구간별 min/max 정보는 옅은 peak층에 남긴다. FFT 막대와 원본 PCM, source/hash 검증, native USB/hardware-volume 코드는 변경하지 않았다. 모든 RMS/표시 변환은 별도 read-only 시각화 데이터에만 적용하며 DSP/음량/bit-perfect 검증 기능이 아니다.

실기기 확인: 재생 중 5초 이상 드래그해 소리/현재 시간이 계속 진행하는지 → 놓을 때 한 번만 위치가 바뀌는지 확인한다. 취소/홈 이동도 음악을 멈추지 않아야 한다. 일시정지 탐색, 드래그 중 새 곡/USB 분리/focus loss, A–B 경계 통과 후 release를 비교한다. 이전에 가득 찼던 곡과 조용한 곡에서 밝은 RMS 본체 높이가 달라지고 피크가 옅게 보이는지 확인한다. Galaxy의 실제 UI/청취 동작은 이 빌드 환경에서 확인하지 못했다.

## v0.4.3: 놓을 때 탐색 / A–B 구간 반복 (이전 동작)

- **드래그 탐색:** 터치를 시작하면 현재 출력을 일시정지한다. 움직이는 동안 파형 커서와 `분:초.소수1자리` 시간만 미리 보여주며 새 위치의 PCM을 전송하지 않는다. 손가락을 놓으면 최종 위치로 한 번만 탐색한다. 원래 재생 중이었다면 재개하고, 원래 멈춰 있었다면 선택 위치에서 일시정지를 유지한다. 키보드/TalkBack의 개별 탐색은 기존 접근성 SeekBar 기능으로 처리한다.
- **취소 처리:** ACTION_CANCEL, 화면 이탈/백그라운드 전환은 선택 위치를 적용하지 않고 멈춘다. 새 곡/다른 탐색/명시적 pause/오디오 focus loss/USB 분리/출력 변경이 있었으면 이전 드래그의 release로 재생을 되살리지 않는다. 길게 드래그해 일시정지 서비스가 종료됐더라도 정상 release 재개 시 foreground service를 다시 요청한다.
- **A–B 사용:** 원하는 시작 위치에서 `A 시작` → 끝 위치에서 `B 끝` → A부터 반복한다. 일시정지 상태에서 파형으로 A와 B를 각각 이동해 지정해도 된다. 최소 구간은 1초다. `해제`는 현재 위치부터 일반 재생으로 돌아가고, A를 다시 지정하면 이전 B는 해제된다. 새 곡/진단 시험 음원을 선택하면 A/B와 횟수가 초기화된다. 활성 구간 밖을 탐색하면 A로 이동하므로 범위 밖 재생은 먼저 해제한다.
- **표시와 우선순위:** 파형에 A/B 마커와 구간 배경, 버튼에 선택 시간, 상태에 완료한 반복 횟수를 표시한다. A–B가 활성화된 동안 곡 전체 반복/자동 다음 곡보다 우선한다. 일시정지와 재개, 화면 잠금/백그라운드에서도 같은 engine의 구간을 유지한다. 프로세스 종료 후에는 보존하지 않는다. 생성된 5초 비교 시험 중에는 A–B 설정을 막아 시험 결과를 바꾸지 않는다.
- **전송 범위:** Android AudioTrack에는 source frame의 `[A, B)`까지만 쓰고 playback head가 소진된 뒤 A로 돌아간다. native USB도 명시적 exclusive end frame까지 source PCM 그대로 제출하며 마지막 packet을 frame 경계에서 줄인다. 시간은 source milliseconds에서 `floor(ms × rate / 1000)` frame으로 변환한다. 비활성화 시 파일의 마지막 부분 frame까지 기존 전체 범위를 유지한다. 매 구간의 buffer comparison/hash는 새로 시작하며 전체 곡 hash와 구분한다.

**무공백 반복은 보장하지 않는다.** USB는 매 반복에서 기존 mute/volume/clock 검증과 장치 초기화를 다시 수행하므로 짧은 공백이 발생할 수 있다. Android도 AudioTrack을 다시 연다. 임의의 두 PCM 지점을 바로 잇기 때문에 경계 파형에 따라 클릭이 날 수 있으며 이를 감추기 위한 crossfade/가공은 하지 않는다. 하드웨어 gain 정책/무변형 buffer 비교는 유지하며, DAC 수신 샘플 또는 물리 반복 경계의 검증을 뜻하지 않는다. `PureBitAudio`의 `scrub_begin/commit/cancel`, `ab_repeat`, `ab_repeat_cycle`, native `PCM output frame range` 및 앱 내부 데이터 보고서로 동작을 확인한다.

실기기 확인: 재생 중 드래그를 길게 유지해 소리가 멈추고 미리보기만 바뀌는지 → 놓았을 때 최종 위치에서 한 번만 재개되는지 확인한다. 일시정지 상태의 탐색, 손을 떼기 전 홈/다른 곡/USB 분리 후 자동 재개 없음도 확인한다. A를 10초/B를 15초로 지정해 3회 이상 반복, 해제, 새 곡 초기화를 Android/지원되는 USB 48·96kHz에서 비교한다. 갤럭시에서의 터치 감각/지연/반복 경계 소리는 아직 확인하지 못했다.

## v0.4.2: 음악 반응형 화면 효과

베이스 펄스, 회로 빛, 파형 탐색 바를 추가했다. **오디오 엔진/USB transport/hardware-volume 코드는 변경하지 않았다.** 그림의 원본은 앱의 private PCM cache이며 물리 DAC나 아날로그 소리의 측정값이 아니다.

- **베이스 펄스:** 기존 source FFT의 낮은16개 band(24Hz부터 대략130Hz까지)의 display energy와 완만한 onset envelope로 링 크기/빛을 조정한다. 정확한 BPM/beat detector가 아니며 무음에 가짜 beat를 만들지 않는다. 강한 저음 후 부드럽게 감쇠한다.
- **회로 신호 흐름:** 원본 PCM의 stereo-average RMS에 따라 밝기/속도를 조절해 기존 회로선을 따라 빛과 짧은 잔상을 이동시킨다. USB 연결 성공/bit-perfect 검증 연출이 아니다. 소스의 반대 위상 stereo가 FFT/평균 RMS에서 상쇄될 수 있다는 기존 분석 한계는 같다.
- **파형 탐색 바:** 전체 PCM을 낮은 우선순위 별도 read-only worker에서 한 번 읽고768개 구간에 모든 채널의 signed min/max를 집계한다. opposite-phase 채널도 파형에서는 지우지 않는다. 표시 폭에 맞춰 peak를 다시 합쳐 전체 곡의 transients를 보존한다. Float 파형은 시각화용 근사치이며 bit comparison 근거가 아니다. 기존 SeekBar의 터치·키보드·접근성 탐색을 유지하며 오디오 탐색은 기존 engine으로 전달한다.

설정 → 빛과 움직임에서 spectrum, 베이스 펄스, 회로 흐름, 파형을 각각 켜고 끌 수 있다. 전체 화면에도 펄스/회로 설정이 적용된다. 시스템 애니메이션이 비활성화되거나 touch exploration이 켜지면 새 장식 모션과 platter 회전은 끈다. source data spectrum은 별도 데이터 표시로 유지된다. 갑작스러운 흰색 flash 대신 제한된 alpha/부드러운 envelope를 쓴다.

파형은 PCM 준비 뒤 그리기 시작하므로 분석 중에는 기본 진행 선과 로딩 문구가 보인다. 큰 곡은 전체 읽기에 시간이 걸릴 수 있다. 화면을 벗어나거나 waveform을 끄거나 source를 교체하면 generation token으로 읽기를 취소하고 늦은 결과를 버린다. 완료한 현재 곡 파형은 해당 View에서 재사용한다. 파형 실패는 기본 탐색 선으로 대체하며 재생을 중단하지 않는다. 출력에 FFT/파형 데이터를 다시 넣는 경로, SRC, software volume 또는 DSP 효과는 추가하지 않았다. 실제60FPS 유지/탐색 touch/음악 연속성/기기 발열은 Galaxy에서 별도 확인해야 한다.

## v0.4.1: USB 음량 조절

v0.4.0은 시험용 -50dB 정책과 볼륨 조작 누락으로 USB Direct에서 휴대폰 volume이 적용되지 않았다. v0.4.1은 DECK의 −/＋, 전경 Activity volume keys, MediaSession relative remote-volume provider를 FU5 하드웨어 control에 연결했다. **실제 실기기 동작은 새 보고서로 확인해야 한다.** Android 출력은 사용자 조작 시 기존 STREAM_MUSIC 음량을 조절한다. 앱 software gain/PCM scaling은 없다.

USB 음악 재생 중 요청한 방향을 native 전송 thread가 적용해 control과 주기적 volume guard를 직렬화한다. 한 단계는 1dB 이상이며 descriptor resolution의 정수 배수로 정렬한다(현재 삼성 이어폰은 1dB). device min/max 이내로 제한하고 SET/readback 및 mute=0 확인이 실패하면 재생을 중단한다. 빠른 중복 요청은 마지막 방향으로 합쳐 한 번에 큰 단계로 점프하지 않는다. UI dB는 device control값이지 실제 음향 크기의 측정이 아니다. MediaSession은 relative control을 사용하므로 시스템의 절대 slider 동작은 vendor별로 제한될 수 있다. 앱 −/＋를 기준 조작으로 사용한다.

사용자가 바꾼 **확인된** 음량은 같은 app/USB연결에서 재개/탐색/다음 곡에 기억한다. 시작은 mute 상태이며 현재 device gain보다 더 크게 자동 복원하지 않는다. 최초 실행/USB분리/Android전환 후에는 remembered gain을 버리고 다시 -50dB 이하에서 시작한다. 일시정지된 USB session은 닫혀 있으므로 음량 조작은 재생 중에만 제공한다. 초기 설정 단계의 -50dB 제한을 벗어나는 것은 사용자의 명시적 작은 단계 조작이며, 최대 음량을 자동 요청하지 않는다. DAC hardwaregain이 활성화된 경로이며 BIT-PERFECT NOT VERIFIED는 유지한다.

새 진단에는 `USER HARDWARE VOLUME: accepted updates`와 마지막 target이 표시된다. 원본/전송 PCM SHA 비교는 음량 변경과 독립적으로 유지된다. 새 시험은 재생 중 −/＋를 한두 번 누르고 물리버튼도 비교한 뒤 진단을 저장해 실제 음량 변화/재생 연속성/SET 실패 여부를 확인한다.

## 이번 버전의 사용법

- 라이브러리에서 폴더 또는 파일을 추가한다. Android 파일 선택기의 읽기 권한만 사용하며 전체 저장소 권한이나 인터넷을 요구하지 않는다.
- 곡을 누르면 재생 대기열을 만들고 준비 후 재생한다. DECK에서 이전/다음, 반복/셔플, 탐색을 조작한다. 대기열 화살표로 순서를 바꿀 수 있다. 목록·폴더 및 최근 재생은 저장되며, 대기열/현재 PCM은 프로세스 내에서 유지된다.
- 기본 출력은 Android다. USB Direct 음악은 **설정 → USB Direct 음악 모드**에서 명시적으로 선택하고 USB 권한을 허용한다. 삼성04e8:a05b의 검증된48/96k profile만 사용하며 무지원 포맷/SHA/control 오류는 전송을 차단한다. USB 재연결은 선택한 모드를 유지하되 자동 재생/Android fallback하지 않는다.
- **설정 → 앱 내부 데이터**에 기존 Diagnostic, USB descriptor/current probe,48/96k 비교 시험, 하드웨어 볼륨 시험, 정책 요청, 검증 범위, 전체 로그 저장/공유를 통합했다. ADB 태그는 기존 `PureBitAudio`를 유지한다.
- 시작 연출과 시각화를 설정에서 끌 수 있다. 첫 새 실행의 약1.5초 무음 회로/로고 연출은 USB 성공이나 검증 결과를 표현하지 않는다. 시스템 애니메이션 비활성화/접근성 터치 탐색에서는 건너뛴다. 복귀/재생 중에는 시작 연출을 반복하지 않는다.

## 시각화와 오디오 처리의 구분

Canvas/Choreographer 데크는60FPS를 **목표**로 렌더링하며 화면이 보일 때만 동작한다. 실제 FPS/발열/프레임 안정성은 Galaxy 실기기에서 확인해야 한다.64개의 로그 주파수 막대는 PCM cache를 읽기 전용 별도 핸들/낮은 우선순위 worker에서 약25회/초 FFT로 분석한 뒤 부드럽게 보간한다. album art는 내장 태그에서 제한 크기로 읽는다. 출처 PCM의 분석 결과이며 DAC/마이크 측정이 아니다. 시각화의 정규화·평활·색상·피크 잔상은 **화면 데이터에만** 적용하고 재생 PCM에는 전달하지 않는다. stereo 평균으로 분석하므로 반대 위상 성분이 시각적으로 상쇄될 수 있다. 아날로그 청취 볼륨은 막대 높이에 반영하지 않는다. 그래픽 실패/파일 교체는 시각화만 조용히 중지하며 재생 경로를 바꾸지 않는다.

## 재생 수명과 지연 개선

전경 mediaPlayback Service, MediaSession, 낮은 우선순위 무음 알림을 사용한다. 알림 권한은 Android13+에서 요청하며 거절해도 앱 내부 재생은 차단하지 않는다. 알림/잠금 화면 조작, 화면 잠금과 백그라운드 재생은 구현했으나 Samsung의 절전 정책을 포함한 실기기 검증은 필요하다. PARTIAL_WAKE_LOCK은 재생/음원 준비 동안만 제한 시간으로 취득·갱신하고 일시정지/오류에서 해제한다. 정지된 Service는30초 후 종료된다. process kill/reboot 후 불확실한 출력 상태에서 자동 음악 재생하지 않는다.

USB 첫 시작 때 source SHA를 검증한 읽기 전용 fd를 프로세스 내에서 유지한다. 재개/탐색은 그 fd와 dev/inode/size/mode/mtime/ctime identity가 유지되는지 검사하고 매 read 전후 stat을 확인한다. 파일 변경/교체/포맷·hash 불일치 시 거부한다. **identity 재사용은 매번 전체 파일 SHA를 재측정한 증거가 아니다.** 보고서의 `PCM validation NEW/REUSED`로 구분하며, 기존 source integrity 결과와 각 전송 구간 reference/payload 비교·SHA는 유지한다. 기존 약2초의 반복 전체 읽기는 재사용되지만 최초 cold 시작에는 여전히 검증 비용이 있다. native96k workaround와 새 PLAY마다 하드웨어mute/quiet-volume handshake는 유지한다. slider의 연속 요청은 최신 target으로 병합한다. native 출력은 mute 상태로 prepare한 뒤 별도 begin에서 요청 취소 fence를 확인하고 음소거 해제/PCM thread를 시작한다. 초기 hash는 block마다, 실제 시작 전후 및 각 submit에서도 취소를 확인하며 정상 취소를 전송 오류로 집계하지 않는다.

음원 준비 중 pause/stop, focus loss, USB detach, output mode 변경은 pending auto-start를 무효화한다. EOF callback도 source generation/재생 의도/PCM 경로를 확인해 오래된 곡 완료가 새 곡을 시작하지 못하도록 한다. 빠른 조작/준비 취소/백그라운드 조건은 모의/코드 검토와 별도로 실기기 확인 대상이다. 하드웨어 볼륨은 여전히 -50dB 이하를 설정·재조회하며 더 낮은 기존 볼륨을 올리지 않는다. DSP/SRC/software gain을 추가하지 않았으며 실제 DAC의 sample identity 및 내부 volume/DSP는 NOT VERIFIED다.

## 새 하드웨어 볼륨 검증과 일반 음악 모드

v0.2의 24/48 저레벨 native USB 전송은 사용자 실기기에서 **240,000 frame / 5초, 오류 0, 전체 PCM/payload SHA-256 일치, 테스트 신호 출력 및 Android 모드의 음악 재생 복귀**까지 확인됐다. 이것은 DAC 수신 샘플의 무변형 증명이 아니다. v0.3 실기기 보고서에서 FU5 mute/volume SET/readback과 24/96 음악의 오류 없는 kernel ISO completion 및 payload hash 일치는 확인됐다. 사용자는 해당 음악 시험에서 소리가 들리지 않았다고 보고했다. **실제 음향 출력/감쇠 및 DAC 수신 샘플은 미검증**이다.

v0.3은 삼성 04e8:a05b의 확인된 playback topology(USB input terminal 4 → FU5 → output terminal 6)를 descriptor에서 다시 검사한다. AudioControl IF0을 claim하고 필요한 경우 사용자 허용 하에 그 driver를 인계받는다. streaming IF2만 인계받던 저레벨 테스트와 달리 microphone 등 해당 USB audio driver의 다른 기능도 잠시 끊길 수 있다. 다른 앱/통화에서 USB 장치를 사용하지 않는 상태로 시험한다.

FU5 master mute, volume GET_CUR/MIN/MAX/RES를 읽는다. 16-bit signed 8.8 dB 형식, 유효 범위/양의 resolution을 확인하며 특수 무한감쇠 MIN/잘못된 값/지원하지 않는 응답은 보수적으로 거부한다. 목표 volume은 **-50 dB 이하**이며, 현재 값이 더 낮으면 높이지 않고 지원 step에 맞춰 더 조용한 쪽으로 정렬한다. positive gain 범위나 원하는 감쇠를 표현할 수 없는 range는 첫 버전에서 지원하지 않는다.

**음악 전송 전 순서:** mute ON SET/readback → 목표 volume SET/readback → 정확한 alternate/clock 설정 확인 → 사용자가 PLAY한 음악에 대해 mute OFF SET/readback → 최초 PCM 전송 직전 volume/mute 재확인. 어느 단계든 실패하면 음악을 전송하지 않는다. 종료 때 원래 mute 상태는 복원하되, 이전의 더 큰 volume을 자동으로 복원하지 않는다. volume/mute를 약 250 ms마다 재조회하며 변경/조회 실패 시 전송을 중단한다. 초기 및 정기 readback은 USB 설정 증거이며 실제 음향 감쇠량/청력 안전을 독립적으로 증명하지 않는다. 외부 버튼/펌웨어/다른 앱에 의한 변경을 한 샘플도 발생하기 전에 차단한다고 보장할 수 없다.

정상 music mode에서는 일반 FLAC/WAV의 원본 PCM을 소프트웨어 감쇠/볼륨 처리 없이 전송한다. **DAC 하드웨어 volume 처리가 활성화되므로 DAC 내부 샘플 무변형을 주장하지 않는다.** APP USB OUTPUT BUFFER 비교/hash와 BIT-PERFECT NOT VERIFIED는 유지한다. 기존 -60 dBFS/30초 test mode는 그대로 별도로 남으며 볼륨 handshake가 실패했다고 일반 음악을 그 경로로 fallback하지 않는다.

### PC 없는 첫 시험 (반드시 귀에서 분리)

1. v0.3 APK를 기존 앱 위에 설치하고 삼성 이어폰을 연결한다. USB 권한을 허용한다.
2. 이어폰을 귀에서 뺀 상태로 DIAGNOSTICS → **하드웨어 볼륨 검증 · PCM 전송 없음** → 안내 확인. 이 시험은 실제 mute/volume 설정을 수행하지만 PCM은 보내지 않는다.
3. 자체진단 파일을 저장/공유한다. `HARDWARE VOLUME — LAST TEST`와 내부 `usb_hardware_volume_test` 로그에 current/min/max/res, target, SET/readback, 실패 이유와 cleanup이 포함된다. 오류가 나면 여기서 멈추고 보고서를 보내면 된다.
4. 설정 시험이 성공한 경우에도 실제 음향 감쇠가 검증된 것은 아니다. 첫 음악 시험은 계속 귀에서 분리한 상태로 한다. **SELECT FLAC / WAV에서 실제 48/96 kHz stereo 원본 음악을 선택**한다. 예전에 확인된 24/48 kHz Stella Jang 파일을 사용할 수 있다. 44.1 kHz를 48 kHz로 변환할 필요는 없다.
5. **USB Direct 음악 · 하드웨어 볼륨 검증** → 안내 확인 → PLAY. 이 버튼은 선택한 원본 파일을 테스트 tone으로 바꾸지 않는다. 매 PLAY/탐색 재시작 시 handshake를 다시 수행하며 실패하면 차단한다. 음량이 작다고 첫 시험에서 버튼/휴대폰 볼륨을 올리지 않는다.
6. 10~20초 후 PAUSE → DIAGNOSTICS → 자체진단 파일 저장/공유. 신호/음악 확인 여부, 오류/끊김 여부를 함께 알려준다. 전체 음원을 재생할 필요는 없다.
7. ANDROID 출력으로 돌아간 뒤 필요하면 기존 음악을 다시 선택해 수동 재생한다. hardware attenuation이 남아 Android 음악도 작을 수 있다. **재생을 정지한 뒤 이어폰을 재연결**하면 driver/기기 초기화에 도움이 된다. Android 재연결 시 시스템이 volume을 다시 설정할 수 있어 앱은 그 이후 값을 보장하지 않는다.

### 구현·검증 한계

native cache를 `pread()` 작은 버퍼로 읽도록 바꿨다. 전체 native source SHA-256을 streaming으로 검증하고, packet별 reference/payload buffer와 완료 구간 hash만 유지한다. hardware-gated mode에서 30초 제한을 해제하지만 기존 source 1 GiB / decoded PCM 2 GiB 한도와 사전 전체 cache 준비는 유지한다. 음원 전체를 native RAM에 올리지 않는다.

현재 volume UI는 고정한 보수적 감쇠만 제공하며 볼륨 UP slider/자동 이전 레벨 복구를 제공하지 않는다. mute·volume이 firmware에서 실제로 적용되는지, Control IF0 takeover/reconnect와 microphone/Android 출력 복구, 긴 음악/96 kHz에서의 안정성은 실기기 보고서로 검증해야 한다. 앱이 부여받은 USB fd의 권한/SELinux 제한이 있으면 오류로 보고하고 우회 성공으로 표시하지 않는다. root/READ_LOGS/DUMP/인터넷 권한은 추가하지 않았다.

모의 native 테스트는 mute-before-volume 순서, SET가 무시되는 경우의 readback 거부, 잘못된 range/resolution, control claim/조회 실패, 첫 packet 직전 volume 변경 시 **0 PCM 제출**, hardware-gated full-scale PCM의 바이트 보존, original mute 복원/더 큰 volume 미복원을 검사한다. 실제 음향 감쇠나 hardware 제어 성공을 mock으로 증명할 수는 없다.

아래 v0.2/이전 버전의 제한 설명은 역사적 기준이며, 새 music mode의 범위는 이 절을 우선한다.

## 이번 프로토타입의 범위

삼성 USB-C 이어폰 **VID/PID 04e8:a05b**의 실제 사용자 descriptor를 바탕으로 별도의 **JNI + Linux usbfs isochronous OUT backend**를 구현했다. 기본은 기존 Android AudioTrack 모드다. USB Direct는 명시적으로 선택한 실험 모드이며 실제 S26 Ultra 전송 성공은 아직 검증하지 않았다. 다른 DAC/USB 장치에는 이 transport를 활성화하지 않는다. 이 버전은 일반 음악의 USB Direct 플레이어 완성본이 아니다.

Android `UsbManager.openDevice()`로 권한을 얻은 fd를 native에서 `dup()`한다. USB `/dev` 경로를 별도로 열거나 루트/숨겨진 Android API를 사용하지 않는다. JNI가 파일/PCM SHA-256, peak 한도, 실제 `USBDEVFS_GET_SPEED`의 FULL speed, VID/PID를 확인한 뒤 streaming IF2를 claim한다. 커널 드라이버가 점유한 경우 사용자가 허용한 실험에 한해 `USBDEVFS_DISCONNECT_CLAIM`으로 해당 interface 인계를 요청한다. 장치 전체 configuration, 마이크 IF1/HID IF3·4, 하드웨어 볼륨은 설정하지 않는다.

정확한 UAC1 alternate를 선택하고 GET_INTERFACE로 확인하며 endpoint 0x03의 sampling frequency를 GET_CUR로 조회한다. 필요하면 원본 48/96 kHz로 SET_CUR한 뒤 GET_CUR 일치를 확인한다. 실제 speed가 HIGH/SUPER이거나 비동기/적응식/feedback/UAC2·3 endpoint이면 미구현으로 거부한다. descriptor rate 문자열을 전송 협상에 재사용하지 않고 구조화한 discrete rate, channel config, slot/valid bits, packet 크기, interval, sampling-frequency control bit를 모두 검사한다.

FULL speed의 1 ms synchronous frame마다 48/96 stereo frame을 원본 바이트 그대로 배치한다. URB당 최대 8개 packet, 최대 4 URB를 queue하며 SUBMITURB/REAPURBNDELAY로 전송한다. short/error/out-of-order packet, 버퍼 불일치, 완료 timeout에서는 즉시 중단한다. 성공한 ISO completion 구간의 source/payload를 deterministic 비교 및 독립 SHA-256으로 검증한다. **커널 완료는 DAC가 같은 샘플을 출력했다는 증거가 아니다.** SUBMIT 성공만으로 DIRECT OUTPUT 상태를 올리지 않는다.

### 안전 제한

USB Direct는 Android system volume을 적용하지 않을 수 있다. **이어폰을 귀에서 뺀 상태에서 테스트한다.** 첫 테스트를 위해 앱이 5초 24-bit/48 kHz stereo WAV(440 Hz, 최대 -60 dBFS, 처음/끝 1초 무음)를 생성한다. 생성된 파일 자체가 원본이며 재생 중 소프트웨어 gain/DSP를 수행하지 않는다.

native는 **30초 이하, 전 파일 PCM peak <= -60 dBFS**를 검사한다. 한 샘플이라도 한도를 넘으면 USB claim/SET/PCM 전송 전에 거부한다. 기존 일반 음악을 자동으로 감쇠/변환해서 재생하지 않는다. 낮은 디지털 레벨이 모든 장치의 청력 안전을 절대적으로 보장하지는 않으므로 첫 실험은 귀에서 분리한 상태에서 한다. 하드웨어/시스템 볼륨 SET 또는 자동 최대 볼륨 변경은 없다.

### PC 없는 실기기 순서

1. 업데이트 APK 설치 → 삼성 이어폰 연결 → DIAGNOSTICS → USB INSPECT / PERMISSION 허용.
2. 기존 24/48 kHz 음악을 **Android 모드**로 재생하면서 `USB 현재 설정 읽기 · READ ONLY`를 누른다. GET_INTERFACE, endpoint GET_CUR, FU5 master volume GET_CUR, native GET_SPEED/capability probe 결과를 확인한다. 이 버튼은 claim/detach/SET/PCM을 하지 않는다. kernel/driver가 읽기를 거절하거나 idle alternate이면 UNKNOWN이다. 실패도 정상적인 플랫폼 제약 자료다.
3. 자체진단 파일을 저장한다. last probe는 조회 시각이 있는 과거 관측이며 현재 DAC 포맷이라고 단정하지 않는다.
4. BACK → `USB Direct 안전 테스트 준비` → **이어폰을 귀에서 분리했다는 안내를 확인하고 허용** → source가 24/48 WAV로 준비될 때까지 기다린다. 자동 재생하지 않는다.
5. PLAY를 누른다. 첫 1초 무음 이후 낮은 레벨의 테스트 신호가 3초 있고 마지막 1초가 무음이다. 신호가 작다고 첫 실험에서 볼륨을 올리거나 귀에 꽂지 않는다. 5초 시험 완료/오류 이후 DIAGNOSTICS → 자체진단 실행 → 파일 저장/공유.
6. 오류가 나도 APK를 바로 삭제하지 말고 진단 파일을 보낸다. errno, claim/detach, clock, submit/reap, 원복 단계가 들어 있다. 실패 시 AudioTrack 자동 fallback 없음.
7. `ANDROID 출력으로 돌아가기`를 누르고 일반 음악을 수동 PLAY하여 출력 복구를 확인한다. USB 장치가 사라졌거나 소리가 안 나오면 **이어폰을 뺐다 다시 연결한다.** 다시 PLAY 전 볼륨을 확인한다. native 종료 후 driver reconnect ioctl 성공만으로 Android route 복구를 보장하지 않는다.

pause/seek/EOF/배경 이동/USB 분리에서는 남은 URB를 취소·회수하고 clock/alternate 복원, interface release, driver reconnect를 시도한다. 원래 설정을 읽지 못했다면 확인된 기준값 또는 idle alternate로 복구를 시도하고 **원래 값 복구 미검증**을 로그에 남긴다. fd를 닫아 남은 URB를 정리한다. native 진행 시간은 **kernel-completed frame 기준 추정치**이며 DAC 재생 head가 아니다. Android AudioDeviceCallback의 ALSA 제거 이벤트는 interface 인계 중 예상될 수 있어 native 세션을 Android route로 전환하지 않는다. 실제 USB 분리 및 native ENODEV/timeout은 중단한다.

### 상태/검증 범위

- `DIRECT OUTPUT`: 앱이 소유한 native USB 세션에서 **성공한 ISO completion**이 관측된 경우만 표시. UI에 kernel completion scope를 명시하며 AudioFlinger/HAL/DSP를 BYPASSED라고 표시하지 않는다.
- `APP USB OUTPUT BUFFER VERIFIED`: 성공한 ISO packet에 대응하는 앱 source/payload bytes 비교/hash 범위. source cache와 native input도 SHA-256을 대조한다.
- `DEVICE PATH NOT VERIFIED / BIT-PERFECT NOT VERIFIED`: 모든 경우 유지. USB clock/alternate 확인, kernel completion, 동일한 앱 버퍼도 DAC 내부 처리·실제 수신 샘플을 증명하지 않는다.

### 빌드·제한·다음 단계

NDK **28.2.13676358**, CMake **3.22.1**, arm64-v8a/x86_64 native library를 추가했다. NDK r28 및 명시적 ELF 16 KiB segment alignment를 사용하며 C++ 표준 라이브러리를 static link한다. libusb/Oboe/libFLAC를 새로 포함하지 않고 기존 정수 decoder/cache를 그대로 사용한다. Linux usbfs 전송은 공개 Android SDK의 안정성 보장 범위 밖이므로 Samsung kernel/SELinux/fd privilege 제한은 실기기 결과로 판단한다. 차단되면 이를 로그로 보고하고 루트 없이 가능한 다른 backend를 검토해야 한다.

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
# Linux 호스트에서 full JDK + g++가 있으면 실제 production transport를 mock usbfs로 검사
tools/test_native.sh
```

native mock tests는 SHA-256 표준 벡터, signed peak gate, packet 크기, 정상 완료, EPERM, short/reordered/corrupt packet, fd cleanup을 AddressSanitizer/UndefinedBehaviorSanitizer로 검사한다. 이 클라우드 sandbox에서는 LeakSanitizer의 ptrace 제한으로 `ASAN_OPTIONS=detect_leaks=0`을 사용한다. 실제 USB/driver/SELinux 동작은 mock으로 검증할 수 없다. 다음 단계는 **이 APK의 read-only probe와 저레벨 테스트 결과 확보**이며, 성공한 후에 hardware volume 안전/feedback/더 긴 재생/다른 DAC 지원을 확대한다.

근거: [Linux usbfs/URB API](https://cdn.kernel.org/doc/html/latest/driver-api/usb/usb.html), [USB Audio Class 1.0](https://www.usb.org/sites/default/files/audio10.pdf), [Android 16 KiB page sizes](https://developer.android.com/guide/practices/page-sizes).

아래 v0.1/v0.1.1 문서는 Android backend와 이전 구현의 기준이다. USB Direct의 최신 구현/제한은 위 내용을 우선한다.

## PC 없이 자체진단하기 (v0.1.1)

기존 APK 위에 v0.1.1 APK를 업데이트 설치한다. 곡을 선택하고 PLAY → DIAGNOSTICS → **자체진단 실행 · PC 불필요**를 누른다. 원본/client 포맷, 활성 route, 장치 지원 rate/profile, 원본용 BIT_PERFECT mixer 정책 노출 여부, source/buffer 검증, 현재 track underrun을 검사한다. 이 버튼은 볼륨·mixer 정책을 변경하거나 새로운 테스트 음원을 재생하지 않는다. USB raw descriptor는 **USB INSPECT / PERMISSION**으로 권한을 허용해야 읽을 수 있다.

진단 결과에서 **공유** 또는 **파일로 저장**을 선택할 수 있다. **진단 + 내부 로그 공유** 버튼은 같은 보고서를 Android 공유 메뉴로 바로 보낸다. 공유 메뉴에서 원하는 앱을 사용자가 선택하거나, 저장한 `PureBit-diagnostics.txt`를 이 대화에 첨부하면 된다. 로그에는 음원명/장치 정보가 포함되며 앱은 이를 자동으로 전송하지 않는다.

보고서는 저장/공유 화면을 열기 **전**, 오디오 worker에서 재생 상태를 캡처하여 고정한다. 따라서 파일 선택기로 이동하면서 재생이 정지되어도 보고서의 `Active`와 원본/client/검증 정보는 캡처 시점 기준으로 유지된다. 캡처 시간과 파일명을 함께 남긴다. 앱의 기존 foreground-only 정지 정책은 유지하며 공유 완료 후 자동 재생하지 않는다. 저장 파일은 Activity 재생성 후에도 이름으로 복구할 수 있다.

예를 들어 원본 44.1 kHz가 USB 장치의 보고 목록 48/96 kHz에 없으면 **시스템 리샘플링 가능성**을 주의로 표시한다. 실제 HAL/DAC rate나 변환 위치가 확인된 것은 아니므로 리샘플링 확정 또는 bit-perfect 실패 확정이라고 표시하지 않는다. 지원 목록이 비어 있으면 미확인으로 남긴다. 모든 결과에 **DEVICE PATH NOT VERIFIED / BIT-PERFECT NOT VERIFIED**를 유지한다.

`PureBitAudio`의 이벤트/오류를 앱 내부의 제한된 메모리 로그(최근 최대 256 Ki 문자)에 함께 보관하고, 보고서에 포함한다. 이전 기록이 잘렸는지 표시하며 다른 앱의 logcat을 읽지 않는다. 앱 재시작 이전 로그는 수집하지 못한다. 완성된 보고서는 앱 내부 저장소에 최근 8개까지 남고 앱 데이터 삭제/앱 제거 시 삭제된다. 공유 provider는 해당 진단 `.txt` 파일에만 일시적인 읽기 권한을 부여하며 음원/PCM cache나 다른 파일은 공개하지 않는다.

**PC 없이 수집할 수 없는 것:** 일반 앱 권한으로 `dumpsys media.audio_flinger`, `dumpsys media.audio_policy`, Samsung HAL/DSP 내부 상태, 실제 USB transaction/DAC 수신 샘플을 얻을 수 없다. READ_LOGS/DUMP 권한, 루트, 셸 권한을 가진 것처럼 처리하지 않는다. 앱 자체진단은 일상적인 보고서 전달에 PC를 없애지만, 실제 Android 내부 믹서 또는 DAC 비트 동일성 증명을 대체하지 않는다. 별도 PC/셸 자료는 가능할 때 보조 증거로만 사용한다.

루팅하지 않은 **Samsung Galaxy S26 Ultra를 목표로 하는 로컬 FLAC/WAV 재생 및 출력 경로 진단용 Android 앱**이다. 화려한 음악 UI보다 PCM 보존, 관측 범위 구분, 실기기 재현 로그를 우선한다. 앱에 인터넷 권한이 없고 재생에 네트워크가 필요하지 않다. 첫 Gradle 빌드의 의존성 다운로드에는 인터넷이 필요하다.

**현재 실제 Galaxy S26 Ultra / USB DAC 테스트 결과는 없다. APK 컴파일 성공은 실기기 출력 검증을 의미하지 않는다. v0.1은 VERIFIED BIT-PERFECT를 표시하지 않는다.** 특정 Samsung 펌웨어/HAL 지원을 가정하거나 AudioFlinger/DSP를 BYPASSED라고 표시하지 않는다. 다른 기기를 빌드/개발 테스트에 사용할 수 있지만 제품의 실기기 검증 대상은 S26 Ultra다.

## bit-perfect의 정의와 상태

원본 파일을 정확히 디코딩한 PCM의 **각 샘플 값, 샘플 순서, 채널 배치, 유효 비트와 재생 sample rate**가 디지털 출력에서 보존되는 것을 목표로 한다. sample rate만 같거나 DAC 화면에 96 kHz가 표시되는 것만으로 샘플 보존을 증명할 수 없다. 표현 컨테이너가 바뀌면 바이트 hash보다 정규화한 정수 샘플 비교가 필요하지만 v0.1은 그런 변환도 수행하지 않는다.

| 상태 | 의미 / v0.1 정책 |
|---|---|
| UNKNOWN | 원본/경로 관측이 부족함 |
| COMPATIBLE | AudioDeviceInfo의 같은 profile에 원본 인코딩/rate/채널이 보고됨. 재생 성공이나 실제 경로 증명이 아님 |
| FORMAT MATCH ✓ | 원본과 AudioTrack **클라이언트** rate/depth/channel이 모두 일치하고 활성 track에 routed device가 조회됨. 물리 DAC 포맷 일치를 뜻하지 않음 |
| DIRECT OUTPUT | 모델에 예약됨. v0.1에서는 실제 direct 경로를 증명할 수 없어 승격하지 않음 |
| VERIFIED BIT-PERFECT ✓ | 모델에 예약됨. 외부 디지털 캡처/검증 장치 근거가 없어 v0.1에서는 승격하지 않음 |

모든 화면/진단에는 **BIT-PERFECT NOT VERIFIED**를 명시한다. `getDirectPlaybackSupport()`의 지원 플래그와 `MIXER_BEHAVIOR_BIT_PERFECT`라는 API 상수명은 실제 DAC 데이터 검증 상태와 별개다.

## Android에서 어려운 이유

일반적인 경로는 앱 → AudioTrack → AudioFlinger/오디오 정책 → Samsung audio HAL/DSP → USB driver → DAC다. 믹서 출력의 rate/depth, system volume, 알림/다른 앱과의 혼합, 벤더 효과, routing 정책이 앱 요청과 다를 수 있다. `AudioTrack.sampleRate`/`format`은 클라이언트 설정을 보고하며 DAC 수신 rate나 HAL의 최종 비트 깊이를 읽어주는 API가 아니다. `AudioDeviceInfo`의 rates/encodings/profiles 역시 지원 capability이며 현재 활성 포맷이 아니다. profile 배열이 비어 있으면 UNKNOWN으로 다뤄야 한다.

`BIT_PERFECT` preferred mixer 정책은 플랫폼 계약상 믹싱/볼륨/효과 없이 HAL에 데이터를 보내도록 요청하는 유용한 방법이다. 그러나 설정 성공과 현재 preference 조회만으로 OEM 구현, 실제 output thread, USB 수신 샘플까지 독립적으로 검증할 수 없다. 실기기 dumpsys 및 외부 검증을 함께 수집해야 한다.

## 선택한 출력 방식

### A. Android output backend — 구현됨

- `AudioTrack.MODE_STREAM`, 정확한 원본 rate/인코딩/mono 또는 stereo channel mask를 요청한다.
- WAV integer PCM16/24/32는 data chunk를 그대로 PCM cache에 추출한다. extensible PCM은 유효 비트와 container 깊이가 같고 mono/stereo 배치가 명확한 경우만 허용한다.
- FLAC16/24는 `jFLAC 1.5.2` 정수 디코더를 사용한다. 플랫폼 MediaCodec의 기기별 출력 깊이에 의존하지 않는다. WAV/FLAC cache를 검증 완료한 뒤 재생한다.
- 앱은 ByteArray PCM을 비동기 worker에서 `AudioTrack.write(..., WRITE_NON_BLOCKING)`으로 전달한다. 부분 write는 받아들인 바이트만 누적하고 미전송 부분을 재시도한다. 탐색은 PCM frame 경계로 정렬하고 track/검증 구간을 다시 만든다. EOF에서 실제 playback head가 제출한 frame까지 진행한 후 정지한다.
- USB AudioDeviceInfo가 있으면 이를 `setPreferredDevice()`로 우선 요청한다. 선호 장치는 실제 route가 아니므로 `routedDevice`도 별도로 확인한다. USB route가 다르거나 변경되면 정지한다.
- API 34 이상 USB에서 `getSupportedMixerAttributes()`를 조회한다. 정확한 format의 DEFAULT attribute를 우선 적용하며, 사용자가 안전 안내 후 허용한 경우 정확한 `BIT_PERFECT` attribute를 우선 요청한다. 성공 여부와 현재 preference를 진단/로그에 표시한다.
- 정책이 노출되지 않거나 거절되면 **FALLBACK ordinary AudioTrack**을 명시한다. PCM 자체를 변환하는 fallback은 없다. 정확한 client format을 만들 수 없으면 오류로 중단한다. bit depth/rate를 낮춰 재생하지 않는다.
- direct/offload 지원 플래그를 조회하지만 PCM hardware offload를 가정하지 않는다. 이 버전의 AudioTrack은 offload/exclusive stream을 만들지 않는다. direct thread 성공/실패는 공개 API로 확정할 수 없어 UNKNOWN이라고 기록한다.
- performance mode는 NONE. 음악 파일 재생은 지연보다 포맷 보존/안정성이 우선이며 LOW_LATENCY는 원하는 rate나 무변형 출력 보장이 아니다.
- pause/seek/파일 교체/종료 시 track을 해제하고 앱이 설정한 mixer preference를 정리한다.

AAudio/Oboe는 검토했으나 v0.1에서는 선택하지 않았다. AAudio EXCLUSIVE/MMAP은 장치/HAL 지원에 따라 SHARED 또는 legacy 경로로 달라질 수 있으며 USB DAC에서 성립한다고 가정할 수 없다. Oboe는 AAudio/OpenSL ES를 감싸는 C++ 계층이며 자체적으로 bit-perfect나 USB 직접 전송을 보장하지 않는다. AudioTrack은 Kotlin에서 PCM24/32와 USB mixer attributes를 정확히 지정하고 클라이언트/실제 route를 진단하는 데 적합하다.

### B. USB Direct backend — 인터페이스/진단만 구현됨

**앱 소유 USB isochronous PCM 전송은 구현하지 않았다. Android 출력으로 소리나는 것을 USB Direct 성공으로 표시하지 않는다.**

Android `UsbRequest`는 bulk/interrupt endpoint 전송을 제공한다. 일반적인 UAC 오디오 streaming은 isochronous OUT, 기기 clock 협상, asynchronous feedback 및 packet scheduling이 필요하므로 이를 `bulkTransfer()`로 대신 구현할 수 없다. Descriptor 분석만으로 재생 엔진이 성립하지 않는다.

v0.1은 USB 권한을 사용자가 요청한 뒤 `UsbDeviceConnection.rawDescriptors`를 **읽기만** 한다. audio interface를 claim/강제 분리하거나 alternate setting/clock을 바꾸지 않는다.

- 제조사/장치명, VID/PID, audio class 및 AC header의 bcdADC를 표시한다.
- UAC1 Type I descriptor의 채널/slot/유효 비트와 discrete/continuous rate를 분석한다.
- UAC2 Type I의 channel configuration, slot/유효 비트를 분석한다. UAC2 rate는 format descriptor에 없으므로 clock tree 및 GET_RANGE/GET_CUR 조회 전에는 **UNKNOWN**이다.
- UAC3, 다른 format type, 복잡한 clock topology는 해석하지 않는다. malformed descriptor는 경고한다.
- descriptor의 지원 alternate와 Android가 실제 선택한 alternate는 별개다. **현재 USB alternate/clock/물리 포맷은 UNKNOWN**이다. Android client 요청과 혼동하지 않는다.

다음 구현 후보는 JNI + native libFLAC + libusb의 asynchronous isochronous transport다. Android USB permission으로 열린 file descriptor를 JNI에 넘겨 `libusb_wrap_sys_device()` 계열로 감싸는 접근을 검토할 수 있다. 이것만으로 Samsung의 interface claim/kernel driver detach/SELinux 제한을 해결한다고 가정하지 않는다. OUT packet size, UAC1/2 clock 요청, feedback endpoint, underrun 복구, detach/reconnect, hardware volume의 안전성을 실기기에서 검증한 뒤 backend를 활성화해야 한다. native 라이브러리는 arm64/16 KiB page size 지원도 필요하다. 검증되지 않은 transport보다 Android backend가 현재 가장 안정적인 실행 선택이다.

## DSP와 볼륨 안전

앱 EQ, ReplayGain, normalization, crossfade, spatial effect, sample-rate conversion, dithering, loudness, software volume 처리는 모두 OFF이며 코드에 처리 경로가 없다. WAV 추출/FLAC 디코딩은 필요한 원본 PCM 복원이다. 앱은 gain API를 호출하지 않고 AudioTrack의 기본 unity gain에 동일한 바이트를 전달한다. 시스템 STREAM_MUSIC 볼륨을 올리거나 100%로 변경하지 않는다. Android/Samsung/DAC 내부 volume 및 DSP 상태는 UNKNOWN이다. 앱에서 Samsung 시스템 효과를 강제로 끄거나 확인할 수 있다고 주장하지 않는다.

**BIT_PERFECT mixer 정책은 기본 OFF.** 이 정책은 system volume도 적용하지 않을 수 있으므로 낮은 휴대폰 볼륨만으로 안전하다고 가정하면 안 된다. 하드웨어 볼륨이 있는 DAC에서 이를 낮추고 이어폰을 귀에서 뺀 후 UI의 `MIXER POLICY OPTIONS`에서 허용해야 한다. 하드웨어 볼륨이 없는 USB-C 이어폰에는 기본 정책을 권장한다. route/device 변경 시 허용을 해제하며 자동 재생하지 않는다.

포커스 상실/duck 요청에서는 PCM을 감쇠하는 대신 정지한다. 앱이 배경으로 이동하거나 화면을 끄면 정지한다. 기기 연결 변경/USB 이탈에서도 정지하지만 OS가 콜백 전에 reroute할 수 있으므로 아주 짧은 다른 출력 노출을 공개 API로 완전히 차단한다고 보장할 수 없다. 테스트는 처음부터 모든 경로의 볼륨을 낮춰 수행한다.

## 현재 구현 기능

SAF 로컬 FLAC/WAV 선택, 원본 metadata 분석, 정수 PCM 디코딩/cache 검증, 재생/일시정지/탐색, USB/일반 출력 장치 감지, 원본/client 포맷 표시, 단순 dark UI, 실시간 Diagnostic, USB descriptor permission/read, 진단 텍스트 저장, `PureBitAudio` 로그가 구현되어 있다. 기본적인 metadata는 codec/rate/depth/channels/duration이며 앨범 tag/앨범아트/라이브러리/인터넷/재생목록/EQ는 구현하지 않았다.

## 검증 가능한 범위

| 검증 | 실제 근거 |
|---|---|
| SOURCE PCM VERIFIED (FLAC) | 전체 디코딩 PCM의 MD5가 파일의 nonzero STREAMINFO MD5와 일치. 모든 frame CRC 오류와 길이 불일치 거부. 추가 SHA-256으로 decoder bytes/cache 재읽기 비교 |
| SOURCE PCM VERIFIED (WAV) | WAV data chunk SHA-256과 추출 PCM cache의 재읽기 SHA-256 일치. 파일 자체의 신뢰성/녹음 원본 진위는 증명하지 않음 |
| MD5 없는 FLAC | decoder/cache SHA-256 일치만 표시. SOURCE PCM NOT VERIFIED 유지 |
| APP OUTPUT BUFFER VERIFIED | AudioTrack이 양수로 받아들인 구간에서 cache bytes snapshot/제출 ByteArray의 deterministic comparison 및 각각의 SHA-256 일치 |
| DEVICE PATH VERIFIED | **불가능/미구현**. system server, HAL, USB transaction 또는 DAC 수신 데이터에 대한 외부 증거 없음 |

버퍼 검증은 현재 play/rebuild/seek 구간의 제출 바이트 수와 두 hash를 표시한다. pause 이후 마지막 구간 결과는 보존한다. write 반환값은 앱 경계를 넘겨 받아들였다는 의미이며 모두 실제로 재생/DAC 수신됐다는 의미가 아니다. pause/seek로 아직 재생되지 않은 큐를 버릴 수 있다. AudioTrack 내부 변환/볼륨/DSP나 USB/DAC 경로는 이 hash에 포함되지 않는다.

외부 디지털 capture를 얻으면 원본과 시간 정렬한 정수 PCM 비교, 채널/clock/컨테이너 정렬을 포함하는 별도 검증이 필요하다. DAC 화면 rate 확인이나 아날로그 loopback은 비트 동일성 증거가 아니다.

## v0.3.1: PC 없는 48/96 kHz 비교

DIAGNOSTICS에 `48 kHz 비교 테스트 준비 · 5초`와 `96 kHz 비교 테스트 준비 · 5초`를 추가했다. 각각 준비한 뒤 메인 PLAY를 명시적으로 눌러 실행한다. 자동 연속 시험/자동 재생/자동 볼륨 증가는 없다. USB INSPECT / PERMISSION에서 먼저 USB 권한을 허용하고 이어폰을 귀에서 뺀 상태로 수행한다. 준비 시 현재 파일이 테스트 WAV로 바뀌므로 음악으로 복귀하려면 원본 파일을 다시 선택한다.

두 WAV는 24-bit stereo, 440 Hz, peak -12 dBFS, 5초이며 첫/끝 1초는 무음이다. 두 sample rate에 맞춰 **각 소스를 직접 생성**하며 재생 PCM resampling/gain은 없다. 이전 저레벨 테스트(-60 dBFS)는 그대로 유지된다. 이번 비교 테스트는 매 PLAY에 기존 하드웨어 -50 dB 이하 설정·재조회 및 음소거 해제 검증을 반드시 사용한다. 더 낮은 기존 하드웨어 볼륨은 올리지 않으므로 두 보고서의 target/재생 중 volume이 다르면 동일 볼륨 비교로 해석하지 않는다. 명목상 -12 dBFS/-50 dB 설정 조합도 실제 소리 크기나 안전을 입증하지 않는다. 볼륨을 올려 가청성을 강제하지 않는다.

`PLAYBACK HARDWARE READBACK`은 전송 직전 및 약 250ms마다 장치에서 읽은 volume/mute의 마지막 값과 성공 조회 횟수다. pause/cleanup에서 다시 mute하므로 이 값은 **재생 중 마지막 관측값**이지 정지 후 현재값이 아니다. 조회 실패/변경 시 전송을 중단한다. 두 시험의 마지막 결과는 `48/96 kHz COMPARISON — THIS APP SESSION`에 보존된다(실패/중도 pause도 구분). 앱을 종료/재생성하면 비교 결과가 사라질 수 있으므로 두 시험이 끝난 뒤 진단 txt를 저장한다. 소리가 들렸는지는 사용자 관측으로 따로 전달하며 성공한 USB 패킷을 가청 출력이나 bit-perfect로 간주하지 않는다.

## v0.3.2: 96 kHz 초기화 재시험

사용자의 비교 결과는 **48 kHz 테스트음은 들림 / 96 kHz 테스트음은 들리지 않음**이다. 두 경로 모두 5초 전 구간 kernel ISO completion, 오류 0, PCM/payload hash 일치, FU5 volume -50 dB 및 mute=0 마지막 관측/20회 재조회를 기록했다. 따라서 96 kHz의 음향 출력 성공이나 DAC sample identity는 입증되지 않았다. 재생 중 모든 순간의 내부 장치 상태까지 관측한 것은 아니다.

기존 코드는 endpoint GET_CUR가 요청 rate와 같으면 SET_CUR를 생략했다. 이 분기가 실제 사용자의 96 kHz 무음에서 실행됐는지 기존 로그는 기록하지 않았다. **firmware clock/state 초기화가 원인이라는 것은 가설**이며 Samsung의 공식 필수 시퀀스로 확인한 내용이 아니다. 이번 버전의 `96K_IDLE_FORCE_SET_V1`은 다음을 시험한다:

1. 기존 하드웨어 mute/quiet-volume 확인을 유지한다.
2. streaming IF2를 claim한 뒤 alt=0(idle)을 SET/GET 확인하고 10ms 대기한다.
3. 원본 bit depth의 alternate를 SET/GET 확인한다.
4. endpoint의 이전 clock report를 기록하고, 같은 값이더라도 요청한 **96000 Hz SET_CUR를 반드시 전송**한다. 3-byte 응답이 아니면 시작을 거부한다.
5. 20ms 후 exact-rate GET_CUR를 확인하고, 다시 20ms 후 재조회하여 같은 rate를 확인한다.
6. clock/alternate 설정으로 하드웨어 control이 바뀌었는지 quiet volume 및 mute=1을 다시 확인한다. mismatch/조회 실패면 음소거 해제/PCM 전송 전에 거부한다.
7. explicit PLAY로 mute=0 SET/readback한 뒤 기존 첫-packet/주기적 volume guard를 거쳐 **원본 PCM 그대로** 전송한다.

10/20ms 대기는 실험적 settling window이며 기기 clock 안정화나 실제 물리 주파수를 보장하는 spec 값이 아니다. SET/GET가 성공해도 펌웨어/DAC가 출력 중인지/정확히 그 clock인지 확정하지 않는다. 추가 silence PCM, PCM SRC, software gain, volume 증가, 자동 fallback은 없다. 48 kHz는 기존 clock SET/skip 순서를 비교 기준으로 유지하되 추가 post-clock hardware-control guard는 동일하게 적용한다.

`INITIALIZATION TRACE`는 해당 native session 시작 기준 상대 ms, idle/active SET_INTERFACE 결과, GET_INTERFACE, SET_CUR 수행/생략/응답, 두 clock readback, packet size, post-clock controls, unmute, 최초 제출/최초 kernel completion을 기록한다. 시작에 실패해도 성공한 앞 단계와 실패 원인을 진단/앱 내부 로그에 남긴다. trace는 logcat `PureBitAudio`에서도 볼 수 있다. 보고서/화면의 버전은 Gradle BuildConfig에서 가져온다(v0.3.1 보고서 헤더에 v0.3.0이 남았던 표시 오류 수정).

실기기 확인: 새 APK 설치 → 귀에서 이어폰 분리 → USB 권한 허용 → DIAGNOSTICS의 **96 kHz 비교 테스트 준비** → 메인 PLAY → 5초 종료/실패 후 보고서 공유. 볼륨을 올리지 말고 이번 테스트가 들렸는지 함께 전달한다. 48 kHz 시험은 원인 비교가 추가로 필요한 경우에만 반복한다. 종료/오류/복구 상태가 불확실하면 재생을 멈춘 뒤 USB를 재연결한다. **96 kHz 개선 여부는 새 기기 보고서가 오기 전까지 미검증**이다.

상태바/내비게이션 바를 투명하게 설정하고 기본 대비용 불투명 scrim을 해제합니다. 앱 창은 display cutout ALWAYS와 edge-to-edge를 사용하며, 정원/가로 달빛/수면은 전체 창에 그립니다. 시스템 아이콘이나 실제 카메라 구멍을 숨기거나 수정하지 않습니다. 버튼·곡 정보·서첩 등 실제 조작부에만 systemBars/displayCutout 여백을 적용해 카메라와 제스처 영역을 피합니다. 가로 조작 패널 폭도 안전 영역을 기준으로 다시 계산합니다. 시작 연출의 건너뛰기 안내는 시스템 하단 바를 피합니다.

API31–34는 명시적 투명 색상과 decor fitting 설정을 사용하며 최신 target의 강제 edge-to-edge 정책에서도 같은 배경/조작부 분리를 사용합니다. Samsung One UI/Good Lock의 3버튼 내비게이션 또는 접근성 설정은 자체 배경/대비 정책을 적용할 수 있으므로 제스처/3버튼, 양쪽 가로 방향과 세로 화면에서 실기기 확인이 필요합니다. 시스템 바는 숨기지 않습니다. 오디오와 내장 가사 처리는 변경하지 않습니다.

### v0.8.3 · Startup recovery

Galaxy에서 v0.8.2가 실행되지 않는다는 보고에 대응했습니다. 아직 실기기 예외 스택이 없어 원인을 확정하지 않았습니다. 복구판은 선택적인 시스템 바 효과를 기본 OFF로 둡니다. 시작 전 창 설정 호출과 v0.8.2의 추가 window 테마 속성을 제거하고, 화면 생성 후에만 선택적인 투명 효과를 적용합니다. API35+에서는 플랫폼의 edge-to-edge를 사용해 조기 decor 생성/불필요한 창 속성 변경을 피합니다. 선택 효과 적용 중 예외가 나면 효과를 끄고 계속 실행하며, 가로 패널 크기 콜백의 재진입/초기 layoutParams 접근도 방어합니다. 설정 → 빛과 움직임 → 시스템 바 투명 효과에서 끌 수 있습니다.

앱 전역의 미처리 Java 예외는 개인 저장소에 제한된 길이로 기록한 뒤 Android의 원래 종료 처리에 넘깁니다. 예외를 숨기거나 재생을 자동 재시작하지 않습니다. 미처리 종료 후에는 다음 실행에서 선택적인 바 효과를 해제합니다. 설정 → 앱 내부 데이터 → **실행 오류 기록 공유**는 이 기록과 Android가 제공하는 본 앱의 종료 사유를 파일로 공유합니다. 인터넷 자동 전송은 없습니다. v0.8.2에는 자체 예외 기록이 없었으므로 이전 Java 스택은 복구하지 못할 수 있으며, OS 종료 사유도 항상 원인을 포함하지는 않습니다.

기존 앱을 삭제하지 않고 같은 서명의 APK로 업데이트하세요. 저장된 라이브러리/가사 연결/테마 선택을 지우지 않습니다. 빌드·단위 테스트·Lint와 실기기 실행 확인은 별개이며, 실제 Galaxy 실행 복구 여부를 설치 후 확인해야 합니다. 오디오/PCM/USB/가사 처리 코드는 변경하지 않았습니다.
