## 횡단보도 신호·속도 상태 (0.26.0, 2026-10-07)

`CinematicTraffic`만 전용 도심의 기존 `TrafficModel.cars`를 제어합니다. 공유 TrafficModel/Geometry/VehicleLayout 및 PNG는 변경하지 않았습니다. 처음부터 신호가 꺼진 Scene은 기존 update를 그대로 사용합니다. 신호를 한번 켠 Scene은 꺼도 속도 상태를 유지해 대기차가 가속·추종 주행으로 돌아갑니다. 새 배열을 만드는 밀도 변경은 신호/속도도 다시 초기화하고, 날씨/테마/구도/밝기와 같은 값의 설정 알림은 진행을 유지합니다.

초록14초/노랑3초/빨강9초의26초 활성시간 순환이며 두 방향을 동시에 제어합니다. 내부60Hz 고정step, 유효 양수dt만 최대0.1초 누적, 그리기/숨김 시간은 진행하지 않습니다. 최초 활성화 시 각 차선의 최소 순항속도와 현재 간격의 정지 가능 속도로 안전한 공통 초기 속도를 정합니다. 차량이 많은 장면에서 여유 간격에 맞춰 자연히 느려집니다. 가속35/감속70은 모델 좌표 단위/s²이며 물리적 km/h가 아닙니다. 다음 속도×step으로 이동하고,1초 추종 여유와 앞차의 다음 감속 가능 속도로 일찍 제동합니다. 실제 전체 차체의 앞/뒤 모델 길이+16과 기존 MIN_GAP150 중 큰 값을 간격으로 사용하고, 같은 tick의 앞차/뒤차 이동량을 함께 제한합니다. 루프가 다른 차량은 화면상의 차체 겹침으로 취급하지 않습니다.

정차 위치는 기존 횡단보도 바깥의 논리y810(접근차 앞/접지점),y902(멀어지는 차의 앞/차체 top)입니다. 후자는 `ground - layout.length(lane,type,ground)=902`를 설정/프로필 변경 때 이분법으로 풀어 모델 위치로 역투영합니다. 렌더러는 이전의 고정 크기 곡선/원본비율·전체차체 할선을 그대로 사용합니다. 반응 대기0.25초와 앞차가 열어주는 간격으로 순차 출발합니다. 정차 직전 아주 작은 잔여 속도는0으로 둬 정차 차량의 미세 기어감을 없앱니다.

노랑 진입 때 정차 거리 < v²/(2×70)+4인 가까운 차량만 통과를 확정하고 빨강에도 계속 진행합니다. 이미 정지선을 지났으면 다음 정지선까지 원형 거리가 크므로 현재 회차를 통과합니다. 먼 접근차를 ‘이미 통과’로 표시하지 않으며 루프/초록 전환 때 통과 결정을 해제합니다. 빨강의 초기에는 진입 확정 차량이 횡단보도를 빠져나갈 수 있습니다. 보행자·교차로 충돌/법규 시뮬레이터는 범위 밖입니다.

프레임 배열을 재사용하며 프레임 자산 디코딩·새 차량 객체·최종 CPU 비트맵은 추가하지 않습니다. 작은 신호 하우징은 보도 두 지점의 픽셀 사각형과 기존 glow 텍스처로 그리며 차량/날씨와 같은 구도 변환을 사용합니다. 제동 상태는 실제 속도 감소/정차hold로 정하고 약0.1초 켜짐/0.25초 꺼짐 완화를 적용합니다. 실제 측정한 뒤쪽 램프와 붉은 반사만 강화하고 앞쪽 램프 색은 유지합니다. 바퀴 물보라 alpha는 실제 속도 비율이며 정차 때0입니다. 비/눈·풍경/열차는 독립 활성 시계로 계속 움직입니다.

새 `traffic_signals` boolean 기본true를 UI/엔진/ScenePreviewView(전체화면 미리보기 포함)/진단·PresetStore에 연결했습니다. v1 프리셋에서 없는 키는true, 있는 키는 엄격Boolean이어야 하며 validation 뒤 같은 Editor로 저장합니다. 추천은true, 초기화는 기본값으로 돌아가고 QuickMode는 해당 값을 쓰지 않아 유지합니다. Android SharedPreferences 알림/JSON 전체 roundtrip은 실기기 확인이 필요합니다.

검사는 `CinematicTrafficChecks`(48조합×90초·3,110,400차량표본/가감속·차체/루프·정차·출발·초기free동등성·dt/15·30·60Hz·노랑가까움/먼접근·토글)와 `CinematicSignalChecks`(실제 팔레트3종·신호 보도 위치/색·정차 앞끝·브레이크/반사·헤드라이트/물보라·설정/그리기 연속성)를 추가했습니다. 기존573,480프로필/672실제 차체픽셀·효과/날씨·99합성과 설정 계산도 통과했습니다. APK 빌드/Lint·서명/버전·13PNG 일치 완료. 실제 GPU/표시FPS·메모리/배터리와 Android 생명주기는 미측정입니다. 다음 확인은 S20+/S26 Ultra의 양방향 긴 차종 정차·24대 재출발·설정/프리셋/숨김·복귀입니다.

## 눈·안개와 선택/전환 캐시 (0.25.0)

기존 마른 세시간대를 image_gen으로 참조 편집해 적설/안개6장을 만들었습니다. 모두841×1870이며 기존 젖음/마름 그림은 보존했습니다. 눈은 지붕/나무/보도에 쌓이고 주행 차선·횡단보도는 제설된 아스팔트에 남도록 요청했습니다. 안개는 먼 산/강/도시부터 층을 만들고 가까운 차선과 건물을 선명하게 유지합니다. 원본과 독립 비교한 중앙선96/횡단보도72표본이 기준을 통과했지만 모든 픽셀·건물 위치 일치를 보장하지 않습니다.

정상(맑음/비)/눈/안개를 별도3가중치 `weatherArt`(ThemeBlend 인스턴스)로 혼합합니다. 최초 configure는 선택 날씨로 snap하고 이후4초 활성update와 재선택을 사용합니다. 정상 가중치는 기존 시간대×노면 혼합을 그린 뒤 눈/안개 이미지 가중치 `weather×theme`를 누적정규화해서 더합니다. 새 눈/안개는 전경과 원경을 모두 포함하는 full-frame 아트이며 정상 마른 노면은 기존처럼 지평선 아래만 대체합니다. ThemeBlend에 target getter와4초 끝점 부동소수 보정을 추가하고 RoadWetness에는 targetValue getter를 추가했습니다.

CinematicArtwork는4종(wet/dry/snow/fog)×3시간대의 지연 캐시를 소유합니다. 기본 노을wet 한 장은 대체용으로 유지하고 현재 혼합의 양수 가중치 및 목표에 필요한 그림만 configure/setTheme에서 디코딩합니다. update는 가중치 변경 후 필요한 집합 밖의 그림을 recycle할 뿐 디코딩하지 않습니다. draw는 로드된 Bitmap만 참조합니다. 전환이 끝나면 가중치0인 다른 시간대/날씨 그림을 해제하고 동일 선택은 활성 캐시를 재사용합니다. 실패한 디코딩은 Scene 수명 동안 기억해 프레임/반복 설정에서 재시도하지 않습니다. 다시 로드하려면 Scene을 재생성해야 합니다.

Wet 시간대 파일은 기준 크기 정확 일치, 나머지 편집 자산은 각 축1픽셀 반올림까지 허용해 같은 논리 구도로 표시합니다. 선택 시간대wet가 실패하면 기본 노을로 대체합니다. 눈/안개 실패는 해당 시간대의 마른 그림(없으면wet)과 기존 눈송이로 대체하며 진단에 표시합니다. 기본wet도 없으면 기존 렌더러로 돌아갑니다. 모든 소유 그림은 해제 시 recycle합니다.

정착한 노을 눈/안개는 캐시2장(약12MiB), 낮/밤은3장(약18MiB)입니다. 정상 노면은 시간대/젖음에 따라1~3장입니다. 시간대와 날씨를 연속 재선택하면 필요한 중간 가중치가3×4종에 남아 최대12장(약72MiB)까지 일시적으로 로드될 수 있습니다. 실제 검사에서도 이 피크12장을 관측했고 이후 노을 안개2장으로 회수됨을 확인했습니다. 수치는 캐시 장수/픽셀 데이터이며 실제 GPU/프로세스 메모리·여러Engine 중복이나 배터리 측정값이 아닙니다. 디코딩은 설정 선택의 동기 작업이므로 첫 변경 시 지연도 실기기 확인이 필요합니다.

SnowModel의48입자를 재사용해 고정 깊이별 크기/alpha와 전/후 레이어를 적용합니다. 가로등 근처 야간 눈송이는 따뜻한 색이며 전환 잔류 눈 가중치가 남으면 계속 움직이고 사라진 뒤 중지합니다. 이전 간격마다 그리던 눈/안개 사각띠는 전용 아트로 대체합니다. 안개 가중치는 가로등 반경·추가 램프 halo, 먼 차체 alpha와 먼 열차 이벤트 alpha에 연결합니다. 차체 폭/길이·기울기/주행 속도/차선 계산은 변경하지 않았습니다. 기존 비/정상 노면은 유지하며 눈/안개 물보라는 없습니다.

`VehicleLighting`는 세단/SUV/택시6500K, 스포츠 쿠페6500K+6500K안개등, 버스/트럭4500K+3000K안개등 프로필과 공통 깊이·시간대·안개 강도를 정의합니다. 4000K이상은 CIE daylight locus, 아래는 Planckian 근사 xy→XYZ→선형sRGB→감마로 정규화하여3000K `#ffb86d`,4500K `#ffe2b9`,6500K `#ffffff`를 얻습니다. 화면의 RGB 표현이며 물리적 색온도/스펙트럼 측정은 아닙니다.

`VehicleLights`는 차체72~99%의 양쪽 바깥 영역에서4방향 연결성분 중 가장 큰 주전조등/후미등을 선택합니다. 앞차 안개등은 주전조등 중심보다 아래쪽 별도 띠(일반차8.5%,상용차4.5% 높이)를 다시 검사하여 작은 주램프 조각을 제외합니다. 기본 아틀라스 스포츠/버스/트럭의 안개등 양쪽이 실제 측정됐고, 대체 팔레트에서 없으면 기본 범퍼 위치를 사용합니다. 앞차 발광 `emission` 마스크는 선정된 그룹의 원본 alpha·명암을 보존하고 색만 변경합니다. 후면은 발광 마스크가 없으며 기존 붉은 제동등을 유지합니다. `wash`는 기존 따뜻한 차체 마스크입니다. 생성/픽셀 스캔은 자산·팔레트 로드 시뿐이고 교체/Scene 종료 때 두 마스크를 해제합니다.

`LightTextures`는3색×발광64×64·반사64×192·전조등64×192·안개등64×96을 한 번 생성합니다. 픽셀 합계417,792bytes(408KiB)이며 실제 GPU/객체 메모리가 아닙니다. 앞쪽 차량은 접지점·차체와 같은 할선 기울기에서 전조등을 길게, 안개등을 짧고 넓게 투사합니다. 정적 `Path`로 지평선 아래 좌우 도로 안쪽만 클립하며 뒤쪽 차량은 전조등 빔을 표시하지 않습니다. 젖은 반사는 동일색을 사용하고3개의 이어진 sourceRect 조각에 작은 횡방향 잔물결만 추가합니다. 차체 크기/위치에는 진동을 추가하지 않습니다. 긴 반사는 젖음0에서 사라지고 후미 반사는 실제 제동 강도를 유지합니다.

낮/노을/밤 가중치는 노면 비춤·램프 번짐을 함께 바꾸고 안개는 노면 비춤을 줄이면서 번짐을 키웁니다. 눈의 기존 따뜻한 가로등 표현을 유지합니다. 가로등은3000K 작은 halo와 도로 안의 국소 pool, `CityLightAnchors`는 기존 노을 아트에서 실제 따뜻한 밝은 창문/간판 최대8곳을 한 번 선택해7px 국소 clip/약한 발광을 추가합니다. 넓고 균일한 밝은 영역은 제외하며 배경 전체 노출/정적 반사를 다시 칠하지 않습니다.

UI 안내와 엔진 진단에 조합을 표시하며 새 설정키·프리셋·권한은 없습니다. PNG13개는0.26.0과 byte동일, 기존 신호/주행/기하/기본4맵은 유지합니다. 최종 Android 빌드/Lint·서명/code27/PNG일치와 새로운 조명검사, 시간대·날씨/신호·차체/99합성이PASS입니다. Android 실제 HW표시/FPS·전력은 기기 확인 전입니다.

## 조명·반사·비 효과 (0.22.0)

VehicleLights는 각 완전 차체의 아래쪽72~96%, 좌우 바깥쪽 영역에서 앞쪽의 밝은 따뜻한 색/뒤쪽의 붉은 색을 측정해 원본 좌표를 캐시합니다. 옥상/택시 표지/버스 안내판은 제외합니다. 찾지 못하면 안전한 기본 위치를 사용합니다. 현재 실제12종 아틀라스와 대체 스프라이트 두 팔레트에서 양쪽 램프 검출을 확인했습니다. 빛과 반사는0.21.0 차체의 폭·길이·접지·할선 변환을 그대로 공유합니다.

실측한 차체 alpha를 넘지 않아 투명 윤곽을 보존하는 차종·방향별 따뜻한 마스크를 자산/팔레트 로드 때 만들고 가로등530/670/810/950/1090의 부드러운 거리 함수로 차체에 덧그립니다. 도로에 사각형 색조가 새지 않으며 팔레트 교체/Scene 해제 때 함께 recycle합니다. 새 마스크는 추가 이미지 메모리와 GPU 업로드/합성 호출을 사용합니다. 수치로 전력·성능 이득을 주장하지 않으며 프레임 전체 CPU 비트맵 생성과 매프레임 픽셀 스캔은 없습니다.

CinematicEffects의 깊이/날씨 함수로 헤드라이트의 따뜻한 빛과 붉은 후미등의 반사 길이·밝기를 조정합니다. 0.22~0.23에는 비가 없는 젖은 그림에도 약한 반사가 남았습니다. 0.24부터 마른 상태는 긴 반사가 사라지고 젖음 값에 따라 길고 진해집니다. 비에서는 반사 alpha만 작게 변화하며 차체 크기에는 시간 진동을 추가하지 않습니다. 반사 텍스처는 기존 캐시를 재사용합니다. 감속/신호 모델 없는 제동등 무작위 깜빡임은 추가하지 않았습니다.

기존 RainModel72/28 입자 풀을 재사용하고 착지 깊이의 크기를0.28~1.4배로 적용합니다. 공중 y는 해당 착지점에서 역산해 물방울·노면 물튀김이 같은 지점에 도달합니다. 먼 비는 차체 뒤, 가까운 비는 앞 레이어입니다. 0.22~0.23은 비가 올 때만, 0.24는 맑음에서도 마르기 전까지 차량당 최대8개 절차적 바퀴 물보라를 표시하고 깊이/강도와 차량 속도에 연결합니다. 별도 객체 풀/타이머를 늘리지 않았습니다. 추가120초 유계 시계는 유효 활성update만 진행하며 숨김/꺼짐에서는 기존 엔진이update를 중지합니다. 기본 맵·시간대/배경 아트/주행 모델·설정은 유지합니다.

## 합성 경로

- `CinematicScene`: 배경·차량 아틀라스·작은 발광/반사 텍스처를 캐시하고 대상 Canvas에 직접 그립니다. 전체 프레임 CPU 비트맵을 만들지 않습니다. 기존 `CityScene`은360×800 소프트웨어 프레임 합성을 유지합니다.
- `TrafficWallpaperService`: 모든 모드에서 Surface의 `lockHardwareCanvas()`를 우선 사용합니다. Android HWUI가 비트맵과 레이어를 GPU로 합성합니다. 자체 OpenGL ES/Vulkan 셰이더 엔진은 아닙니다. Canvas 호출·차량 시뮬레이션·입자 계산은 CPU에서 수행합니다.
- Surface 첫 HW 연결 전 실패에만 SW로 고정합니다. HW 연결 후 일시 실패는 해당 프레임을 건너뛰고 HW를 다시 시도하여 HW/SW producer를 같은 Surface에서 교대하지 않습니다. Surface 재생성 때 연결 상태를 초기화합니다. lock와 제출 시 Surface 소멸 예외를 처리합니다.
- `ScenePreviewView`: Android View의 Canvas에 같은 전용 장면을 직접 그립니다. 전체 비율/15fps와 기존 포커스·가시성 중지 정책을 유지하며 다른 모드로 바꾸면 전용 자원을 해제합니다. 진단에는 홈 배경 엔진 기록만 저장합니다.
- 자산 누락·손상/불러오기 실패 시 기존 장면으로 복귀합니다. 차량 아틀라스만 잘못되면 기존 차량을 사용합니다. 자산은 모드 활성화 시 로드하고 해제는 반복 호출에도 안전합니다.
- 배경 자체의 창문·가로등·수면 반사는 정적 아트입니다. 이동 차량에는 별도 조명·노면 반사를 합성하고 비·눈·안개·구름 추가 효과와 작은 전철을 활성 시간으로 진행합니다. 전철은 교량 높이와 강 구간에 클립하여 앞 건물을 가로지르지 않습니다. 물리 기반 반사는 아닙니다.

기본 배경/기존 대체 차량/효과 픽셀 데이터 약6.29MiB에 새 아틀라스 약6.00MiB가 추가됩니다. 이는 `width×height×4`로 계산한 이미지 데이터이며 실제 프로세스 메모리 측정값이 아닙니다. 0.20.0의64×64 접지 그림자는16KiB가 추가됐고 차량 자세 float 배열은 재사용합니다. 0.22.0에서 원본 차체 크기의 따뜻한 마스크12종과 작은 대체 차량 마스크12종이 추가됐습니다. 정확한 소스 alpha를 유지하며 소유 객체가 해제합니다. 기본 장면 캐시, 모델, 엔진/미리보기 중복, GPU 드라이버 복사와 객체 메모리가 별도로 들 수 있습니다.
