# Cinematic scene desktop validation

This tool compiles the production `CinematicScene` and its traffic/weather/event models against the existing Java2D graphics adapter plus desktop asset-decoding adapters. These adapters are outside `app/src` and never enter the Android APK.

From `pixel-traffic`, use a full JDK (the managed environment JDK is shown below):

```bash
JAVA_HOME=/workspace/toolchains/jdk-21.0.8+9 tools/cinematic-preview/run.sh --checks
JAVA_HOME=/workspace/toolchains/jdk-21.0.8+9 tools/cinematic-preview/run.sh /workspace/artifacts/pixel-traffic-cinematic.png app/src/main/assets
```

The exported 540×1200 PNG uses the production scene's asset-loading and drawing path with 24 cars, strong rain, and enabled scene events. It is a desktop composite, not an Android screenshot. The check runner exercises asset loading/failure, multiple viewport shapes, normal/close camera positions, density/weather/brightness variations, opaque output, drawing twice without time advancement, visible changes after time advancement, and lifecycle release.

For 0.20.0 it also runs independently measured lane landmarks and 28,704 complete vehicle poses, including lane clearance, perspective headway and offscreen continuation. Uneven atlas-row fixtures and all twelve native sprites guard against adjacent-row contamination. Another 120 poses check the native opaque pixels for width, lane containment and ground alignment. Cropped views may contain no cars briefly, so visible time advancement is observed over up to twelve active seconds.

For 0.21.0, `VehicleLayoutChecks` densely samples 114,696 poses per profile at 0.25 px depth steps, checking monotone width/length, continuous size and heading rates, constant source aspect, whole-body secant alignment, lane clearance and headway. Synthetic, conservative and three actual Scene palette profiles total 573,480 poses. The Geometry check separately scans 114,696 size samples and retains the 28,704 complete-body checks. Another 672 opaque-pixel footprints call the production Scene vehicle path across palette 0→1→2→0, guarding actual atlas/fallback dimensions and profile refresh. The existing 33 full composites and asset/graphics checks still run.

For scoped patches, use `tools/check-patch.sh cinematic`; it includes these geometry checks. See [patch guide](../../../docs/PATCH_GUIDE.md) to avoid duplicate suites and unrelated history scans.

For 0.22.0, `CinematicEffectChecks` runs 12,105 depth/weather samples and 100 rain landing depths, independent asymmetric lamp fixtures with a bright roof decoy, source-alpha wash containment, all 12 real atlas lamp pairs and fallback lamp caches, wet/dry production reflection/spray, near/far production rain layers, speed-linked spray time, invalid elapsed time, draw-only clock stability, and release. The Bitmap adapter now implements `setPixels` for cached source masks; desktop helpers remain outside the APK. The existing size/lane and 33-composite suite still runs. Warm body masks are exact cropped source silhouettes, allocated at asset/palette load and recycled with their owner; this adds image memory and draw calls that require device measurement.

For 0.23.0, `CinematicThemeChecks` validates same-size day/sunset/night assets with 24 median-stripe samples relative to the original and 18 independently sampled crosswalk anchors. Solid-color fixtures independently prove correct source-over weighted blending, selected startup artwork, smooth retargeting and four active seconds. Two production scenes compare every car position and cached pose through 180 ticks and multiple theme changes; artwork identity, corrupt/mismatched variant fallback and bitmap release are checked. Automatic hour boundaries are reused from `SceneTimePolicy`. Full compositions expand from 33 to **99** cases across all three themes. These are desktop checks; Android setting notifications, local clock changes and hardware memory use still need devices.

For 0.24.0, `CinematicSurfaceChecks` adds an independent six-color oracle for simultaneous time/surface blending, preserving the original upper sky, instant weather startup, smooth four-active-second drying and retargets, invalid time, actual 180-tick/24-car pose preservation, dry fallback and cache/release. The artwork suite now checks **48 median landmarks and 36 crossing anchors** across six backgrounds. The generated dry day image is 842×1869 (one native pixel rounding); the dry loader allows at most one pixel per axis and maps it to the unchanged logical bounds. Other backgrounds remain 841×1870. Effect checks verify residual spray/reflection during drying and stop only at the dry endpoint. All 99 composition cases remain. Dry images are cached once and released with the three wet images; their added decoded pixel data is about18MiB, not measured GPU/heap usage.

Export snow with weather argument3 and fog with4, with theme0/1/2. Reuse the final compiled class directory to generate the six needed previews. Images are decoded synchronously on configuration selection, never in frame update/draw; device selection latency and hardware bitmap lifecycle need on-device checks. New weather assets are full-frame; normal dry art retains the original upper sky.

The preview accepts an optional final theme index (0 day, 1 sunset, 2 night) after dimensions:

```bash
JAVA_HOME=/workspace/toolchains/jdk-21.0.8+9 tools/cinematic-preview/run.sh /workspace/artifacts/day.png app/src/main/assets 10 6 2 0 1 540 1200 0
```

After the final suite has compiled unchanged inputs, invoke `CinematicRenderPreview` directly with its retained class directory to export the required three theme PNGs without recompiling or rerunning suites.

Java2D draws some blends and transformed bitmap edges differently from Android. These checks validate composition and guard against software-path crashes; they do not validate hardware Canvas behavior, GPU upload cost, Android frame rate, memory pressure, battery use, or on-device lifecycle. The generated PNG should be visually inspected alongside a real-device screenshot before reporting art direction as validated on Android.

For 0.26.0, the full runner also compiles `CinematicTraffic` and runs `CinematicTrafficChecks` and `CinematicSignalChecks`. The controller suite covers 48 density/type/speed combinations for90 active seconds (3,110,400 car samples), body-front stops on both sides, bounded acceleration/deceleration, circular and physical gaps, wraps, queue holds/staggered departure,15/30/60Hz equivalence, invalid/resume time, initially disabled legacy parity, smooth disable/re-enable, and near/far amber entry. The pixel suite uses the actual atlas plus both fallback palettes to verify sidewalk signal colors/placement, actual body-front stops, brake-tail/reflection pixels, unchanged headlights, stopped/moving spray and settings/draw-clock continuity. Existing artwork and geometry checks remain unchanged.

After fixing a failed stage, recompile changed classes into the retained build directory and resume that stage. `CinematicTrafficChecks --edges` skips the long trajectories when their inputs already passed unchanged; no argument runs all trajectories. Unknown arguments fail. Do not report edge-only runs as full trajectory validation. Android preference notification, JSON roundtrips, GPU/actual device performance remain separate.

For 0.27.0, the runner compiles `VehicleLighting`, `LightTextures`, and `CityLightAnchors`, and runs `CinematicLightingChecks`. The suite checks independent 3000/4500/6500K RGB reference ranges and six requested vehicle profiles; 10,020 bounded depth/weather gain samples; independent main/fog fixtures with roof and fragmented-headlamp decoys; all twelve actual atlas pairs and separate sports/commercial fog anchors; source-alpha containment and cache lifecycle. The graphics adapter now implements transformed `clipPath` and a triangle fixture checks it. Low-alpha bitmap RGB can quantize through premultiplication: visible pixel warmth and integrated alpha-weighted beam RGB are tested instead of demanding strictly different channels at every transparent edge. Source/profile CCT values remain independently checked. Full-source PNGs are unchanged; emissive masks and small textures are procedural caches.
